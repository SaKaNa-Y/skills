# Browse working records on request

`browse-records` gives users a read-only view of recorded problems, assessments, handling decisions and evidence. It requires explicit user invocation. It preserves the current records as the source of truth and labels their freshness; it does not refresh remote status or reassess findings.

The view separates Findings and Explorations, preserves problem identities across files and shared PRs, and exposes missing records and conflicting summaries. Users can filter, sort and request item or group details. The default conversation view links back to original records. Category and keyword filters retain the active-record scope unless the user changes it.

An independent three-turn fixture exercise covered missing index entries, conflicting assessments, a missing primary file, shared repair work and separate member acceptance. Its first version included closed identities in a later filter denominator. The method was revised to preserve lifecycle scope, and a fresh session passed the affected overview and filter sequence. A read-only walkthrough of a real documentation repair group preserved three separate acceptance results and their evidence limits. Input hashes confirmed the fixture records were unchanged. A separate inactive-routing probe answered an ordinary question without loading the skill; invocation configuration was also parsed and checked. These bounded checks support record-view fidelity, not universal browsing accuracy or measured usability improvement.
