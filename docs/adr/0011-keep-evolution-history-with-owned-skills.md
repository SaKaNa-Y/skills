# Keep Evolution History with Owned Skills

Detailed history helps resume work and explain decisions, but most experiments and private recovery inputs do not help a public reader. Sanitizing every historical artifact would still publish a large activity archive. This repository therefore keeps detailed history locally and publishes selected summaries. This refines [ADR 0005](0005-preserve-skill-evolution-history-and-reversal-evidence.md) without requiring a separate records repository.

Use `.local/skill-evolution/` for detailed per-skill histories, shared discussions, retained evidence and migration ledgers. This ignored directory is deliberately outside ordinary Git backup. Use `docs/skill-evolution/` for reviewed summaries of adopted changes, identity transitions and maintenance decisions. Summaries retain local sequence identities, so public sequences may have gaps. Each public record explains the problem, result, evidence and limits without depending on private files.

Own histories follow the skill's current or last name. Renames update navigation and identity metadata while historical evidence keeps original names. Retired skills retain their history; splits and merges link prior owners. External skills used during a task do not become owned histories. Shared decisions have one record with links from affected skills.

Preserve meaningful failures, No Change outcomes, alternatives and paused checkpoints locally. Pause retains the next action and does not imply abandonment. Evidence retention does not require every trial to remain runnable. Prefer minimal fixtures, observed results and recoverable Git states over complete environments. Private configuration snapshots remain local. Temporary environments and undecided migration inputs have separate ignored locations.

The public CI validates the complete publishable checkout. An explicit local-history check validates the private archive's structure and integrity. Both reject missing declared inputs; only public mode applies publication warnings. Automated checks neither decide publication value nor certify privacy. [Repository policy](../agents/evolution-history.md) defines the operational boundary, and [validation](../agents/validation.md) defines the checks.

Keeping all sanitized history tracked was rejected because storage and publication serve different purposes. A separate private repository was also rejected in favor of one checkout. The accepted cost is that detailed local history requires an independent backup if one is later desired; no backup mechanism is implied or created here. Replacing unpublished commits may remove a draft archive from the publishable branch only under explicit authorization. Adding a later deletion commit would leave those contents in its ancestors.
