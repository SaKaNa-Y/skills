# Comparison scope and engineering record updates

Date: 2026-10-24. Source-only change.

A feedback shortlist can hide unresolved outcomes from earlier discussions. Assess now compares those outcomes with the author's commitments and the available implementation evidence before selecting feedback. A conditional reference extends the existing worklist, preserves narrow questions and distinguishes suggested mechanisms from user outcomes.

An eligible engineering record can still receive unrelated follow-up content. The shared save checkpoint now extracts the substantive engineering update before writing and checks the saved content for both inappropriate additions and omitted contributions. Design drafts, replay commands, implementation, delivery and resource work remain eligible. Correspondence follows its explicit document-saving request; wording-only turns leave an accurate engineering account unchanged.

Independent review and staged local agent trials supported the change. Both versions handled scope comparison, so no comparative improvement is claimed there. The baseline saved a wording-only change into an engineering record; the candidate avoided that write. An early candidate still retained correspondence-curation narration. Revisions removed that residue and preserved legitimate engineering next actions. Repaired scenarios started with an earlier candidate and continued with the final instructions; a separate fresh final-version control checked implementation, verification, delivery and conditional cleanup. These results support bounded adoption, not general reliability or a complete fresh paired trial of the final version.
