# Share Working Records Across Discovery and Implementation

Use Working Records to preserve observations before qualification and to carry evidence, assessments and user decisions from discovery into implementation. Keep them separate from the canonical issue tracker: requiring issue-ready evidence before capture loses the observations needed to recognize related problems, while treating every observation as an issue overstates its status. Assess owns common judgment and Finding Relationships; Just retains actual usage, Yak retains the active-task boundary and reconciliation, and Explore retains opportunity discovery and discussion. Related findings retain distinct identities unless they share a resolution and acceptance boundary.

One coordinator manages assignments across co-active workflows. Responsibility does not require a separate agent: select delegation by independent progress, resource ownership and the value of the handoff, and reuse the responsible worker when continuity matters. This revises the mandatory separate-worker aspect of ADRs 0007 and 0009 while preserving accountable assessment, bounded reconciliation, evidence gates and formal tracker approval. Working-record capture has its own configured authority; canonical tracker writes remain subject to Tracker Write Approval.

Setup supports global defaults and project overrides, with the current explicit instruction taking precedence. It supplies guidance that consumers read directly, including ordinary chats; it does not become a runtime scheduler. Delivery writeback and on-access reconciliation keep known PR coverage current without promising continuous synchronization. PR state, assessment, execution progress and record lifecycle remain separate. Archive inactive records with their reasons and relevant evidence; deletion is explicit rather than an automatic consequence of merge.

The selected implementation entry, implement-change, reuses an Implementation Agreement, claims work, implements proportionate outcome slices, reviews and verifies the integrated result, and returns a Draft PR with evidence and record writeback. PR merging is outside its responsibility. These are accepted design boundaries; runtime skill changes implement them while real-use effectiveness remains pending. Setup can configure explicit local-commit authority for each record kind, with one commit per new record or substantive update; prior opportunity-only permission does not silently extend to other kinds.
