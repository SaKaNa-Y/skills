# Keep target preparation active until the audit can run

A source audit can produce many observations without verifying its selected target. An incomplete build followed by broad use of old artifacts does not answer that target's user outcomes. Existing completion rules rejected this result, but a repeated execution still stopped after an agent-selected offline attempt.

Just Use It now makes target preparation the next task before starting the affected journeys. The recovery reference turns each failure into a concrete action: inspect actual execution conditions, distinguish external constraints from chosen restrictions, perform authorized preparation, and retry. A comparison artifact answers a named recovery question before work returns to the selected target. Independent ready slices can continue.

A blocker identifies the next required action and the evidence that prevents it. User restrictions and actual access denials remain boundaries. Explicitly selected releases still qualify through their own identities. The change adds no installation authority and requires no new tool.

Validation used a fresh execution against Vite+ source. Starting from an offline failure on an uncached dependency, the agent fetched dependencies, completed new native/core/CLI builds, and exercised formatting and selective lint diagnostics. A separate controlled HTTP 403 case retained the source target as blocked while an explicitly selected release passed its own CLI checks.

A corrected child-install replay used a private store and preserved the sampled host-cache metadata and tested artifact hashes.
