# Assess Findings Through Phased Evidence Handoffs

Usage observations, defect judgments, and recommendations to change a product answer different questions. Reproducing a behavior does not establish that it violates an expected outcome; absence of a mandatory fix does not defeat a worthwhile optional improvement. Repeatedly challenging an unfixed proposition made recommendations drift while the underlying facts stayed unchanged.

Introduce the model-reachable `assess-findings` workflow, automatically reached by Just Use It and Yak Shaving Triage and backed by the existing `investigate-with-evidence` method. One accountable assessment worker per bounded finding set preserves the scenario, expected-outcome basis, impact and response goal. It separates classification from action value and revises only judgments affected by new evidence, a corrected inference, or changed requirements. This borrows fixed baselines and independent judgment dimensions from code review without turning dependent assessment questions into opposing reviewers.

This extends [the experience/publication boundary](0003-separate-experience-from-finding-publication.md). Just owns actual usage and replayable evidence, including relevant source-discovered repository environments. Early assessment runs against supplied evidence and public-use contrasts; source-dependent inquiry waits for the source phase, and tracker history waits for frozen independent coverage. Yak owns record reconciliation and returns its evidence to the same assessor. Search may begin with enough evidence to compare identity before the final recommendation, avoiding a circular readiness requirement. Repair and publication remain separately authorized.

Keeping assessment solely in Yak would mix recording with recommendation ownership and leave Just-only audits without the method. Repeated explicit challenge calls would leave users coordinating the workflow and invite shifting propositions. Duplicating assessment rules in both callers would allow drift. The shared workflow costs a declared installation dependency and coordinated worker state; missing dependencies or capacity remain explicit rather than silently producing unassessed final judgments. Neither a new worker nor passing a tracker gate makes earlier source-informed work blind again.

Repository environments add state and integration coverage, but their availability does not make every script a required capability or every isolated result a product-wide finding. Record the exercised relationship and confirm consumer behavior when the claimed impact depends on it.
